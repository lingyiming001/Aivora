# 用户长期记忆与角色会话

长期记忆按登录用户保存，跨角色会话使用，不随聊天清空或删除而清除。游客不记录。个人中心可查看、修改、删除，或关闭自动记录与上下文使用；关闭保留数据库记录。

## 数据与记录规则

V24 创建 `user_memory`：`(user_id,memory_key)` 为主键，记录内容、来源（CHAT/USER）和更新时间。支持喜欢、不喜欢、爱好、回复偏好四类，每类保存最新一条，手动内容最多300字。

聊天事务在接收有效消息后，只从用户原文提取明确的中文句式：`我喜欢…`、`我偏爱…`、`我不喜欢…`、`我讨厌…`、`我的爱好是…`、`我希望你以后/今后…`，允许前缀`请记住，`，每段最多80字。不调用额外模型，不分析助手回复、附件正文，不追溯旧历史。当前是有界的规则实现，不是语义理解；虚构角色用第一人称表达的喜好仍可能被记录，可在个人中心修正或关闭。

每次聊天读取该用户当前偏好，作为注明“仅作参考数据”的用户消息置于角色规则后、最近最多40条消息前。用户偏好不作为系统指令。关闭时不注入。删除后再次明确表达同类偏好会重新记录。

接口均从当前认证身份确定用户，不接受客户端传入userId：

- `GET /api/user/memories`：开关及记忆列表。
- `PUT /api/user/memories`：`{"enabled":false}`。
- `PUT /api/user/memories/{key}`：`{"content":"科幻小说"}`。
- `DELETE /api/user/memories/{key}`：删除一类偏好。

## 一个角色一个活跃会话

`POST /api/chats`先返回已有活跃会话；数据库部分唯一索引约束`(user_id,character_id) WHERE deleted_at IS NULL`，并发创建用upsert返回同一ID。删除后可以重新创建。

V24 将已有重复活跃会话合并到最近使用的会话，迁移消息、请求、图片和文件归属；旧会话行软删除。合并前用`chat_message.history_hidden`标记已清空消息，合并后列表、历史和模型上下文继续排除它们。消息原始ID、扣费请求和钱包账本保持不变。

## 生成图片

生成图片卡和放大预览均可直接“加入聊天框”，使用服务端attachmentId，不下载或重新上传图片。点击后进入待发送附件区，由用户发送。加入按钮不再依赖识图配置，但发送时仍需现有视觉描述链路成功；供应商失败保持原有报错及不扣聊天费用逻辑。
