# 聊天语音一致性

## 本轮发现

此前请求已经固定`voice=Cherry`，没有随机选择音色。可控的不一致来源包括：`language_type=Auto`、每次重新打开页面后重新合成同一回复、消息内播放器的倍速/静音状态随组件重建而重置。不能据此断言供应商的不同文本声线变化完全由这些因素造成。

## 会话参数与音频保存

V25在`chat_session`保存首次使用的TTS模型ID与名称，以及音色和语种（默认`Cherry`/`Chinese`）。第一次朗读时绑定可用模型，后续不随模型列表顺序变化而切换；原模型被停用、改名或配置失效时，新合成明确报错，不静默换模型。已有音频可在供应商停用后继续回放。

请求保留原多模态TTS接口，发送固定音色和语种；正文先去常用Markdown包装，再取前600个UTF-16单元，并避免截断代理对。超长仍提示“朗读前600字”。未增加未验证的seed或指令参数。

每条回复首次成功合成后下载WAV保存到`chat_speech_audio`，缓存键包含模型名、音色、语种、实际朗读文本；每条音频最多16MiB，校验RIFF/WAVE头。后续朗读复用原始字节，供应商临时URL过期不再触发重新合成。此版本音频存于PostgreSQL，存储量随语音消息增长。

`POST /api/chats/{id}/media/speech`返回`audioUrl/truncated/voice/language/model`；`GET /api/chats/{id}/media/speech/{messageId}/audio`返回授权WAV。两条路由均校验会话所有权；隐藏或清空的消息不能继续读取。音频随消息物理删除级联删除，聊天清空沿用原逻辑隐藏。

## 播放器

前端以带认证的Blob请求读取音频，再创建本地object URL。一个会话内复用播放器的倍速/静音设置；切换消息不重置。显式启用`preservesPitch`，变速不重新开始播放。切换会话/卸载回收object URL，客户端最多保留8条音频；服务端缓存保持可重播。

## 验证与边界

- Java21聊天模块53测试通过，覆盖参数不可用不换音色、模型停用后缓存可用、授权、文本清理、600字截断、缓存键和WAV校验；后端打包通过。
- 前端生产构建通过；原有Vite大包提示保留。
- V25在隔离副本验证默认值/外键并回滚；本地正式迁移成功。
- 真实合成三条中文短句，模型/音色/语种一致；各自重播SHA-256完全一致；跨用户与清空后读取返回404。测试语音及报告在`.agents/test/stable-speech/`。
- 浏览器使用隔离接口与测试WAV检查倍速、音高保持和缓存；不会播放真实用户音频。

固定参数与缓存保证应用不换配置、同一条音频重播不变；不同句子的自然语调或供应商采样差异仍可能存在，未做声纹相似度或人工听感定量评估。模型名称是供应商别名时，也不等同于锁定了供应商内部模型版本。

接口依据：[阿里云Qwen-TTS API](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。官方说明支持指定`voice`与`language_type`，并建议单一语种明确指定目标语种；这不是对声线完全相同的保证。
